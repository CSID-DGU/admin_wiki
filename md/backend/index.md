# Backend

사용자가 서버 사용을 신청하고 관리자가 승인 버튼을 누르면, 그 뒤로는 사람 손을 거치지 않고 Ubuntu 계정 생성부터 컨테이너 배정, 만료 알림까지 전부 자동으로 처리됩니다. Admin BE(Spring Boot)는 그 자동화를 실제로 돌리는 서버이고, 이 섹션은 그 코드를 넘겨받아 유지보수해야 하는 사람을 위한 문서입니다.

GitHub 레포: [CSID-DGU/admin_be](https://github.com/CSID-DGU/admin_be)

## 무엇을 하는 서버인가

**목적**: 예전에는 서버 사용 신청을 관리자가 수작업으로 처리해서 병목·실수·자원 방치가 잦았습니다. Admin BE는 신청 접수부터 계정 생성, 만료 회수까지 전 과정을 자동화해 이 문제를 없애려고 만들어졌습니다.

**기능**: Admin BE가 직접 담당하는 일은 다음과 같습니다.

- 사용자/관리자 인증 및 권한 관리
- 서버 사용 신청 접수, 승인/거절 처리
- 승인 시 Infra Server에 Ubuntu 계정 및 K8s 컨테이너 생성 요청
- 만료일 기반 컨테이너 자동 회수 및 사용자 알림 발송
- 장기 미접속 계정 자동 비활성화

**컴포넌트**: Admin BE는 아래 컴포넌트와 통신하며 동작합니다. 전체 흐름 다이어그램은 [개요 2. 전체 구조](개요.md)에 있습니다.

| 컴포넌트 | BE와의 관계 |
| --- | --- |
| Admin FE | REST API로 신청·승인·조회 요청을 받음 |
| MySQL | 신청 내역, 사용자 정보, 포트 매핑 등 운영 데이터 저장 |
| Redis | RefreshToken, Slack 알림 큐, 이메일 인증/중복 방지 키 저장 |
| Infra Server (config-server) | 승인 시 Ubuntu 계정·K8s Pod 생성 요청, 만료 시 정리 요청 |
| Gmail / Slack | 승인·만료 예고·삭제 완료 등 주요 이벤트를 사용자·관리자에게 통보 |
| Prometheus | BE 지표 수집 |

## 용어

아래 약어는 이 섹션의 여러 문서에서 설명 없이 반복해서 나옵니다. 코드를 보기 전에 알아두세요.

| 약어 | 뜻 |
| --- | --- |
| TTL | Time To Live. 저장된 값이 자동으로 삭제되기까지 남은 시간입니다. 이 문서 세트에서는 대부분 Redis 키의 만료 시간을 가리킵니다. 예를 들어 "5분 TTL"은 저장 후 5분이 지나면 그 키가 알아서 사라진다는 뜻입니다. |
| AT / RT | AccessToken / RefreshToken의 줄임말입니다. OAuth 스펙 용어가 아니라 이 프로젝트에서만 쓰는 표현이며, 두 토큰을 나눈 이유와 동작은 [인증·보안](인증-보안.md)에서 다룹니다. |
