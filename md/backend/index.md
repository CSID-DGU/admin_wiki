# Backend

사용자가 GPU 서버 사용을 신청하고 관리자가 승인하면, 리눅스 계정과 컨테이너가 만들어지고, 기간이 끝나면 다시 회수됩니다. Admin BE(`admin_be`, Spring Boot)는 이 과정의 **기록과 판단**을 맡는 서버입니다. 이 섹션은 그 코드를 넘겨받아 고치고 운영할 사람을 위한 문서입니다.

GitHub 저장소: [CSID-DGU/admin_be](https://github.com/CSID-DGU/admin_be)

## 한눈에 보기

| 질문 | 답 |
| --- | --- |
| 무엇을 하는 서버인가 | 회원·신청·승인·만료를 관리하고, 실제 계정·컨테이너 작업은 인프라 서버(config-server)에 맡긴다 |
| 직접 하지 않는 일은 | 리눅스 계정 생성, 컨테이너 생성·삭제, 포트 열기 — 전부 config-server가 한다 |
| 가장 중요한 개념은 | **작업 등록 후 결과 확인**. 승인 버튼은 작업을 등록만 하고 바로 돌아오며, 결과는 몇 초마다 따로 확인해 반영한다 |
| 데이터는 어디에 | MySQL(신청·사용자 등 영구 기록), Redis(로그인 유지, 알림 대기열, 횟수 제한) |
| 배포는 어떻게 | push로는 배포되지 않는다. admin_infra의 배포 워크플로를 사람이 실행한다 ([브랜치·배포 규칙](../브랜치-규칙.md)) |

## Admin BE와 주변 구성요소

| 구성요소 | Admin BE와의 관계 |
| --- | --- |
| Admin FE | 화면. 모든 요청을 REST API로 보낸다 |
| MySQL | 사용자, 신청, 그룹, 포트, 경고 등 운영 기록 저장 |
| Redis | 로그인 유지용 토큰, Slack 알림 대기열, 메일 인증번호, 횟수 제한 |
| config-server | 계정·컨테이너·포트·그룹·비밀번호 작업을 실제로 실행 |
| Kubernetes API | 관리자 화면의 Pod 상태·로그·이벤트 조회 (읽기 전용) |
| Gmail / Slack | 사용자 안내와 관리자 알림 |
| Prometheus | 대시보드에 보여 줄 GPU 사용률·컨테이너 수 조회 |
| Google Sheets | 운영 환경에서만, 발급 내역을 스프레드시트에 옮겨 적음 |

## 자주 나오는 용어

| 용어 | 뜻 |
| --- | --- |
| 신청(Request) | 컨테이너 하나를 쓰겠다는 요청 한 건. 승인되면 컨테이너 하나와 1:1로 묶인다 |
| 변경 요청(ChangeRequest) | 이미 쓰고 있는 컨테이너에 대한 요청. 기간 연장, 그룹 추가, 포트 변경, 비밀번호 변경 |
| 우분투 계정 | 컨테이너에 SSH로 들어갈 때 쓰는 리눅스 계정. 신청이 아니라 **사람**에게 하나씩 붙는다 |
| 작업(job) | config-server에 등록하는 일 한 건. 생성·회수·이동 등 여덟 종류가 있다 |
| 폴러(poller) | 등록한 작업의 결과를 몇 초마다 물어보고 DB에 반영하는 예약 작업 |
| 회수 | 컨테이너나 계정을 지워 자원을 돌려받는 일 |
| 스택 | 같은 코드를 띄운 독립 환경 하나. 운영은 `operation`, 시험용은 `baseline`·`noprobe`·`full` |
| TTL | 저장한 값이 저절로 사라지기까지의 시간. 주로 Redis 키에 쓴다 |
