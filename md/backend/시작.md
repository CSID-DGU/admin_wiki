# 시작

내 컴퓨터에서 Admin BE를 띄우고 테스트를 돌리기까지의 순서입니다. 위에서부터 차례로 따라 하면 됩니다.

## 한눈에 보기

| 준비물 | 버전·비고 |
| --- | --- |
| JDK | 17 |
| MySQL | 8.x. 빈 데이터베이스 하나만 만들어 두면 표는 서버가 뜰 때 자동으로 생긴다 |
| Redis | 로컬에 하나. 비밀번호 없이 기본 포트로 충분하다 |
| IDE | IntelliJ 권장 (학생 계정이면 Ultimate) |
| 설정 파일 | `application.yml` — 저장소에 없으므로 팀에서 받아야 한다 |

테스트만 돌릴 거라면 MySQL·Redis·설정 파일이 **모두 필요 없습니다.** 4절로 바로 가세요.

## 1. 저장소 받기

```bash
git clone https://github.com/CSID-DGU/admin_be.git
cd admin_be
```

브랜치는 `main` 하나입니다. 작업 브랜치 이름과 PR 규칙은 [브랜치·배포 규칙](../브랜치-규칙.md)을 따릅니다.

## 2. 설정 파일 준비

`application.yml`에는 DB 비밀번호, 메일 계정, Slack 주소 같은 비밀값이 들어 있어 저장소에 올리지 않습니다(`.gitignore` 등록).

1. 팀 Notion의 BE 페이지에서 `application.yml` 내용을 받습니다.
2. `src/main/resources/application.yml`로 저장합니다.
3. 파일 맨 위 `spring.profiles.active`가 `local`인지 확인합니다.
4. `local` 프로파일의 DB 주소·계정·비밀번호와 Redis 주소를 내 환경에 맞게 고칩니다.

!!! warning "설정을 바꿨다면"
    `application.yml`은 저장소에 없어서 PR에 드러나지 않습니다. 키를 추가하거나 바꿨다면 PR 본문에 적고, Notion 페이지와 배포 환경의 설정도 함께 고쳐야 합니다([운영 가이드](운영-가이드.md) 4절).

모든 환경에 똑같아야 하는 값(메일 발송 제한 시간, 예약 작업 스레드 수 등)은 설정 파일이 아니라 코드(`RuntimeDefaults`)에 기본값으로 들어 있습니다. 설정 파일에 같은 키를 쓰면 그 값이 우선합니다.

## 3. DB와 Redis 준비

MySQL에 빈 데이터베이스를 만듭니다.

```sql
CREATE DATABASE web_admin;
```

**표는 직접 만들지 않습니다.** 서버가 뜰 때 Flyway가 `src/main/resources/db/migration`의 SQL 파일을 번호 순서대로 실행해 스키마를 만듭니다. Hibernate는 엔티티와 스키마가 맞는지 확인만 합니다(`ddl-auto: validate`). 스키마를 바꾸는 방법은 [도메인 설명](도메인-설명.md) 마지막 절에 있습니다.

Redis는 Docker로 띄우는 것이 가장 간단합니다.

```bash
docker run -d -p 6379:6379 --name redis redis
```

## 4. 테스트 실행

```bash
./gradlew test
```

테스트는 메모리 DB(H2)와 가짜 설정값(`src/test/resources/application.yml`)만 쓰고 외부 서비스에 닿지 않습니다. 그래서 MySQL·Redis·실제 설정 파일 없이도 돌아갑니다.

```bash
# 클래스 하나만
./gradlew test --tests "DGU_AI_LAB.admin_be.domain.users.service.TokenServiceTest"
```

PR을 올리면 CI가 `./gradlew build`(테스트 포함)를 돌리고, 통과해야 병합할 수 있습니다. 테스트 종류와 작성 규칙은 [코드 컨벤션](코드-컨벤션.md) 12절을 봅니다.

## 5. 서버 실행

IntelliJ에서 `AdminBeApplication`을 Run 하거나 터미널에서 실행합니다.

```bash
./gradlew bootRun
```

`http://localhost:8080/`에 접속해 `OK`가 보이면 떠 있는 것입니다.

로컬에서는 config-server가 없으므로 **승인·회수처럼 인프라 작업이 필요한 기능은 끝까지 진행되지 않습니다.** 승인하면 신청이 "처리 중"에 머뭅니다. 가입·로그인·신청 접수·조회까지는 로컬에서 확인할 수 있고, 그 뒤 흐름은 실험 스택에서 확인합니다.

## 6. API 문서(Swagger) 켜기

API 문서는 기본으로 꺼져 있습니다. 로컬에서 보려면 `application.yml`의 `local` 프로파일에 아래를 넣습니다.

```yml
springdoc:
  api-docs:
    enabled: true
  swagger-ui:
    enabled: true
```

서버를 다시 띄우고 `http://localhost:8080/swagger-ui/index.html`에 접속합니다.

## 7. 인코딩 설정 (IntelliJ)

알림 문구 파일(`messages.properties`)의 한글이 깨지지 않게 합니다.

1. Settings → Editor → File Encodings
2. Default encoding for properties files를 `UTF-8`로
3. Transparent native-to-ascii conversion 체크

## 8. 막혔을 때

| 증상 | 확인할 것 |
| --- | --- |
| 뜨자마자 DB 연결 오류 | 데이터베이스 `web_admin`이 있는지, `local` 프로파일의 계정·비밀번호·포트가 맞는지 |
| 뜨다가 스키마 검증 오류 | 엔티티만 고치고 Flyway 파일을 추가하지 않았는지 |
| 뜨다가 Flyway 체크섬 오류 | 이미 적용된 `V…sql` 파일을 고쳤는지. 고치지 말고 새 번호로 추가한다 |
| Redis 연결 오류 | Redis가 떠 있는지, 설정의 주소·포트·비밀번호 |
| 한글이 깨짐 | 7절 설정. 이미 깨진 파일은 원본으로 되돌린다 |
| 테스트가 "ApplicationContext 로드 실패"로 끝남 | `./gradlew clean test`로 빌드 결과를 지우고 다시 실행 |
| 8080 포트 사용 중 | 그 프로세스를 끄거나 `server.port`를 바꾼다 |

여기까지 됐다면 [개요](개요.md)로 넘어갑니다.
