# 에러 코드 카탈로그

API가 실패했을 때 돌려주는 상태 코드와 메시지는 모두 `ErrorCode` enum 한 곳에 있습니다. 화면에서 본 오류의 원인을 찾을 때, 새 오류를 추가하기 전에 비슷한 것이 있는지 확인할 때 봅니다.

위치: [`error/ErrorCode.java`](https://github.com/CSID-DGU/admin_be/blob/main/src/main/java/DGU_AI_LAB/admin_be/error/ErrorCode.java)

## 읽는 법

실패 응답은 항상 같은 모양입니다.

```json
{ "status": 409, "message": "승인을 기다리는 신청이 이미 있어요. …", "code": "CONTAINER_REQUEST_ALREADY_PENDING" }
```

| 필드 | 내용 |
| --- | --- |
| `status` | HTTP 상태 코드 |
| `message` | 사용자에게 보여 줄 문구. 입력 검증 오류면 어긴 규칙의 설명이 들어간다 |
| `code` | `ErrorCode`의 이름. 화면은 이 값으로 분기한다 |

상태 코드가 뜻하는 바는 다음과 같습니다.

| 상태 | 뜻 | 사용자가 할 일 |
| --- | --- | --- |
| 400 | 입력이 잘못됐다 | 입력을 고친다 |
| 401 | 로그인이 필요하거나 만료됐다 | 다시 로그인한다 |
| 403 | 로그인은 됐지만 권한이 없다 | — |
| 404 | 대상이 없다 | — |
| 409 | 지금 상태에서는 할 수 없다 | 메시지의 안내를 따른다 (대개 "끝난 뒤 다시") |
| 422 | config-server가 요청 내용 때문에 거절했다 | 요청 내용을 확인한다 |
| 429 | 너무 자주 요청했다 | 잠시 뒤 다시 |
| 502 | config-server 등 바깥 서비스가 실패했다 | 잠시 뒤 다시. 반복되면 관리자가 확인 |

!!! note "401은 화면이 다시 로그인시킨다"
    화면은 401을 받으면 로그인 만료로 처리해 다시 로그인하게 합니다. 로그인이 풀려야 하는 상황에만 401을 쓰고, 단순히 입력이 틀린 경우에는 400을 씁니다. 새 오류의 상태 코드를 정할 때 화면의 반응을 함께 생각합니다.

## 1. 공통

| 코드 | 상태 | 나오는 때 |
| --- | --- | --- |
| `BAD_REQUEST` | 400 | 입력 검증 실패. 메시지에 어긴 규칙이 담긴다 |
| `INVALID_INPUT_VALUE` | 400 | 요청 본문을 읽을 수 없다 (형식 오류) |
| `MISSING_REQUEST_PARAMETER` | 400 | 필수 파라미터가 없다 |
| `UNAUTHORIZED` | 401 | 인증 실패. 내부 토큰이 틀렸을 때도 이 코드 |
| `FORBIDDEN` · `ACCESS_DENIED` | 403 | 권한 없음 (관리자 경로를 일반 사용자가 호출) |
| `RESOURCE_NOT_FOUND` · `ENTITY_NOT_FOUND` | 404 | 경로나 대상이 없다 |
| `METHOD_NOT_ALLOWED` | 405 | 그 경로에 없는 HTTP 메서드 |
| `CONFLICT` | 409 | DB의 중복 금지 제약에 걸렸다 |
| `INTERNAL_SERVER_ERROR` | 500 | 예상하지 못한 오류. **로그를 봐야 한다** |
| `EXTERNAL_API_ERROR` | 502 | 바깥 서비스 호출 실패 |

## 2. 로그인·토큰

| 코드 | 상태 | 나오는 때 |
| --- | --- | --- |
| `INVALID_LOGIN_INFO` | 401 | 이메일이 없거나 비밀번호가 틀렸다 (둘을 구분해 알리지 않는다) |
| `TOO_MANY_LOGIN_ATTEMPTS` | 429 | 15분 안에 다섯 번 틀렸다 |
| `ACCOUNT_DISABLED` | 401 | 비활성화된 계정 |
| `INVALID_ACCESS_TOKEN` | 401 | `Authorization: Bearer …` 헤더가 없거나 형식이 틀렸다 |
| `INVALID_ACCESS_TOKEN_VALUE` | 401 | 서명이 틀렸거나 비밀번호를 바꾸기 전에 발급된 토큰 |
| `EXPIRED_ACCESS_TOKEN` | 401 | 액세스 토큰 만료. 화면이 토큰을 다시 받는다 |
| `INVALID_REFRESH_TOKEN_VALUE` | 401 | 리프레시 토큰의 서명이 틀렸거나 비밀번호 변경 전에 발급됐다 |
| `EXPIRED_REFRESH_TOKEN` | 401 | 리프레시 토큰 만료. 다시 로그인 |
| `NOT_MATCH_REFRESH_TOKEN` | 401 | 저장된 토큰과 다르다 (다른 곳에서 로그인했거나 이미 한 번 쓴 토큰) |
| `AUTHENTICATION_FAILED` | 401 | 인증 처리 중 예상하지 못한 오류 |

`ACCOUNT_DISABLED`가 404가 아니라 401인 이유: 로그인한 채로 비활성화된 사용자의 요청이 조용히 실패하지 않고, 화면이 다시 로그인 안내를 띄우게 하기 위해서입니다.

| 코드 | 상태 | 나오는 때 |
| --- | --- | --- |
| `USER_NOT_FOUND` | 404 | 사용자가 없다 |
| `USER_ALREADY_ACTIVE` · `USER_ALREADY_INACTIVE` | 409 | 이미 그 상태인 사용자를 활성화·비활성화하려 했다 |
| `USER_ALREADY_HAS_ROLE` | 409 | 이미 가진 권한으로 바꾸려 했다 |
| `LAST_ACTIVE_ADMIN` | 409 | 마지막 관리자를 내리거나 비활성화하려 했다 |
| `UBUNTU_USERNAME_NOT_ASSIGNED` | 409 | 우분투 계정 이름을 등록하지 않고 신청했다 |
| `UBUNTU_USERNAME_ALREADY_ASSIGNED` | 409 | 이미 등록한 계정 이름을 바꾸려 했다 |
| `UBUNTU_ACCOUNT_ALREADY_ASSIGNED` | 409 | 생성 결과의 계정 번호가 이 사용자에게 이미 배정된 번호와 다르다 |
| `UBUNTU_ACCOUNT_RELEASING` | 409 | 리눅스 계정을 회수하는 중이다 |
| `UBUNTU_USER_DELETION_FAILED` | 502 | 계정 회수 작업을 등록하지 못했다 |
| `USER_REQUEST_CLEANUP_PARTIALLY_FAILED` | 502 | 사용자의 컨테이너·계정 정리 일부를 시작하지 못했다 |
| `FORBIDDEN_REQUEST` | 403 | 남의 신청·계정을 대상으로 요청했다 |

`UBUNTU_ACCOUNT_ALREADY_ASSIGNED`가 보이면 계정 번호가 어긋난 것입니다. 신청은 `PROCESSING`에 남고 관리자에게 알림이 갑니다. 원인을 확인하기 전에 되돌리지 않습니다.

## 5. 비밀번호

| 코드 | 상태 | 나오는 때 |
| --- | --- | --- |
| `UBUNTU_PASSWORD_REQUIRED` | 400 | 리눅스용 비밀번호 해시가 없다. 다시 로그인하면 만들어진다 |
| `UBUNTU_PASSWORD_CHANGE_FAILED` | 502 | 비밀번호 작업을 등록하지 못했다. 비밀번호는 바뀌지 않았다 |
| `UBUNTU_PASSWORD_CHANGE_WHILE_PROVISIONING` | 409 | 컨테이너를 만드는 중이라 비밀번호를 바꿀 수 없다 |
| `PASSWORD_RESET_REQUEST_NOT_FOUND` | 404 | 재설정 신청이 없다 |
| `PASSWORD_RESET_IN_PROGRESS` | 409 | 새 비밀번호를 컨테이너에 반영하는 중이다 |
| `PASSWORD_RESET_ALREADY_CLOSED` | 409 | 이미 적용됐거나 거절된 신청이다 |

`UBUNTU_PASSWORD_REQUIRED`는 SSH 비밀번호가 웹 비밀번호로 합쳐지기 전에 가입한 계정에서 납니다. 원문을 볼 수 있는 때가 로그인뿐이라, 로그인할 때 해시를 만들어 채웁니다.

## 6. 신청

| 코드 | 상태 | 나오는 때 |
| --- | --- | --- |
| `INVALID_REQUEST_STATUS` | 409 | 지금 상태에서는 할 수 없는 동작. **가장 자주 보는 코드** |
| `CONTAINER_REQUEST_ALREADY_PENDING` | 409 | 결정을 기다리는 신청이 이미 있다 |
| `TOO_MANY_CONTAINER_REQUESTS` | 429 | 하루 다섯 건을 넘었다 |
| `SLACK_MEMBERSHIP_REQUIRED` | 409 | Slack 워크스페이스에서 이름·이메일이 같은 회원을 찾지 못했다 |
| `HOME_CLEANUP_IN_PROGRESS` | 409 | 그 계정의 홈 폴더를 정리하는 중이다 |
| `USER_SUSPENDED` | 403 | 이용 정지 중이다 |
| `USER_APPROVAL_ALREADY_IN_PROGRESS` | 409 | 같은 사용자의 다른 신청을 만드는 중이다 |
| `PENDING_GROUP_IN_PROGRESS` | 409 | 같은 새 그룹을 만드는 다른 신청을 반영하는 중이다 |
| `PROVISION_JOB_IN_PROGRESS` | 409 | 생성 작업이 끝나지 않아 거절할 수 없다 |
| `RESOURCE_GROUP_NOT_FOUND` · `GROUP_NOT_FOUND` | 404 | 고른 GPU 묶음·그룹이 없다 |

`INVALID_REQUEST_STATUS`는 이미 승인·거절된 신청을 다시 처리하려 할 때, 진행 중인 신청에 다른 동작을 겹치려 할 때, 같은 작업이 config-server에서 이미 돌고 있을 때 납니다. [시스템 아키텍처](시스템-아키텍처.md) 1절의 상태 그림에서 지금 상태와 하려는 동작을 맞춰 보면 원인이 보입니다.

## 새 오류를 추가할 때

1. 이 문서에서 비슷한 코드가 있는지 먼저 찾습니다.
2. `ErrorCode`의 관련 묶음에 추가합니다.
3. **상태 코드**는 위 "읽는 법"의 표를 기준으로 고릅니다. 특히 401은 화면이 로그아웃시킨다는 점을 기억합니다.
4. **메시지**는 화면에 그대로 보입니다. 무엇이 문제이고 무엇을 하면 되는지 한 문장으로 씁니다.
5. 이름은 한 번 정하면 바꾸지 않습니다. 화면이 이 이름으로 분기합니다.
6. 이 문서의 표에 추가합니다.

## 지금 쓰이지 않는 코드

`ErrorCode`에 남아 있지만 현재 코드 어디에서도 던지지 않는 값입니다. 예전 기능의 흔적이므로 새 코드에서 쓰지 않습니다.

`INVALID_REFRESH_TOKEN`, `FILE_UPLOAD_FAILED`, `JSON_PARSING_FAILED`, `DUPLICATE_NAME`, `INVALID_PASSWORD`, `SLACK_USER_EMAIL_NOT_MATCH`, `NO_AVAILABLE_GROUPS`, `NO_AVAILABLE_RESOURCES`, `NODE_NOT_FOUND`, `USER_CREATION_FAILED`, `INVALID_USERNAME_FORMAT`, `POD_CREATION_CONCURRENCY_LIMIT`
