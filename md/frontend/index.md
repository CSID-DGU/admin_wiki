# Frontend

사용자는 이 화면에서 가입하고 GPU 컨테이너를 신청하며, 관리자는 같은 화면의 관리자 콘솔에서 신청을 승인하고 컨테이너와 사용자를 관리합니다. Admin FE(`admin_fe`, React)는 이 **웹 화면**입니다. 이 섹션은 그 코드를 넘겨받아 고치고 배포할 사람을 위한 문서입니다.

GitHub 저장소: [CSID-DGU/admin_fe](https://github.com/CSID-DGU/admin_fe)

## 한눈에 보기

| 질문 | 답 |
| --- | --- |
| 무엇을 하는 프로그램인가 | 브라우저에서 도는 화면. 모든 데이터는 Admin BE의 REST API(`/api/...`)로 주고받는다 |
| 직접 하지 않는 일은 | 판단과 저장. 신청 가능 여부, 권한, 상태 전이는 전부 Admin BE가 정하고 화면은 그 결과를 보여 준다 |
| 가장 중요한 개념은 | **작업 등록 후 결과 확인**. 승인·재시작·이동 버튼은 서버에 작업을 등록만 하고, 화면이 몇 초마다 결과를 물어 완료를 안내한다 |
| 기술 스택 | React 19, Vite, React Router 7, Tailwind 4, i18next. 상태 관리 라이브러리와 HTTP 라이브러리는 쓰지 않는다 |
| 배포는 어떻게 | push로는 배포되지 않는다. admin_infra의 배포 워크플로가 이 저장소를 nginx 이미지로 빌드해 올린다 ([브랜치·배포 규칙](../브랜치-규칙.md)) |

## Admin FE와 주변 구성요소

| 구성요소 | Admin FE와의 관계 |
| --- | --- |
| 브라우저 | 빌드된 JS·CSS를 받아 실행한다. 로그인 토큰을 `localStorage`에 둔다 |
| nginx (같은 컨테이너) | 빌드 결과를 내려 주고, `/api/`를 Admin BE로 넘기며, 보안 헤더를 붙인다 |
| Admin BE | 유일한 데이터 출처. 인증, 신청, 승인, 컨테이너 상태 조회를 모두 여기에 묻는다 |
| config-server | 화면이 **직접 부르지 않는다.** 진행 단계 같은 정보도 Admin BE가 대신 받아 준다 |
| ingress-nginx | 클러스터 밖에서 들어오는 HTTPS를 받아 이 화면의 nginx로 넘긴다 |
| Google Fonts, Clarity, Google Analytics | 글꼴과 방문 분석. 그 밖의 외부 스크립트는 보안 정책(CSP)으로 막혀 있다 |

## 화면은 둘로 나뉜다

| 영역 | 주소 | 누가 쓰나 |
| --- | --- | --- |
| 사용자 포털 | `/user/...` | 모든 로그인 사용자. 신청, 내 컨테이너, 변경 요청, 마이페이지 |
| 관리자 콘솔 | `/admin/...` | `ADMIN` 권한 사용자. 신청·변경 요청 승인, 컨테이너·사용자·이미지·안내 문구 관리 |

관리자는 상단의 전환 버튼으로 두 영역을 오갈 수 있습니다. 로그인·가입·비밀번호 재설정은 두 영역 밖에 있습니다.

## 자주 나오는 용어

| 용어 | 뜻 |
| --- | --- |
| 신청(Request) | 컨테이너 하나를 쓰겠다는 요청 한 건. 승인되면 컨테이너 하나와 묶인다 |
| 변경 요청(ChangeRequest) | 쓰고 있는 컨테이너에 대한 요청. 기간 연장, 그룹 추가, 포트 변경, 비밀번호 변경 |
| 우분투 유저네임 | SSH 접속에 쓰는 리눅스 계정 이름. 웹 계정 하나에 하나, 한 번 정하면 바꿀 수 없다 |
| DECS | 화면의 이름이자 자체 디자인 시스템(`src/design-system`)의 이름 |
| 폴링(polling) | 결과가 나올 때까지 같은 조회를 몇 초 간격으로 반복하는 것 |
| NodePort / 공개 포트 | 클러스터가 컨테이너에 배정한 포트와, 밖에서 실제로 접속하는 포트. 서버마다 바꾸는 규칙이 다르다 |
| 스택 | 같은 코드를 띄운 독립 환경 하나. 운영은 `operation`, 시험용은 `baseline`·`noprobe`·`full` |
