# 시작

내 컴퓨터에서 Admin FE를 띄우고 린트·빌드를 돌리기까지의 순서입니다.

## 한눈에 보기

| 준비물 | 버전·비고 |
| --- | --- |
| Node.js | 24 (CI와 Dockerfile이 같은 버전을 쓴다) |
| pnpm | 10. `npm install -g pnpm@10` |
| Admin BE | 화면을 실제로 써 보려면 하나 필요하다. 로컬에 띄우는 방법은 [backend 시작](../backend/시작.md) |
| 편집기 | 자유. ESLint 확장을 켜 두면 3절의 경고를 편집 중에 바로 본다 |

린트와 빌드만 확인할 거라면 Admin BE가 **필요 없습니다.** 3절로 바로 가세요.

## 1. 저장소 받기

```bash
git clone https://github.com/CSID-DGU/admin_fe.git
cd admin_fe
pnpm install
```

브랜치는 `main` 하나입니다. 작업 브랜치 이름과 PR 규칙은 [브랜치·배포 규칙](../브랜치-규칙.md)을 따릅니다. 의존성을 추가하거나 올렸다면 `pnpm-lock.yaml`도 함께 커밋합니다. CI와 이미지 빌드가 `--frozen-lockfile`로 설치하므로, 잠금 파일이 어긋나면 그 자리에서 실패합니다.

## 2. API 주소 정하기

화면은 API를 `VITE_API_BASE_URL` + `/api/...` 주소로 부릅니다. 이 값은 **빌드할 때** 코드에 박히므로, 바꾸면 개발 서버를 다시 띄워야 합니다.

| 파일 | 저장소에 있나 | 쓰는 곳 |
| --- | --- | --- |
| `.env.production` | 있음 | 배포 이미지. 값이 비어 있어 같은 주소의 `/api/`로 요청하고, nginx가 Admin BE로 넘긴다 |
| `.env` | 없음(`.gitignore`) | 내 컴퓨터. 아래처럼 만든다 |

로컬 Admin BE에 붙일 때는 저장소 루트에 `.env`를 만듭니다.

```bash
VITE_API_BASE_URL=http://localhost:8080
VITE_NODE_ENV=development
```

이때 브라우저가 화면 주소와 다른 주소(8080)로 요청하므로 Admin BE의 CORS 허용 목록에 개발 서버 주소가 있어야 합니다. Admin BE `application.yml`의 `deployment.frontend.local`이 `http://localhost:30081`인지 확인합니다.

!!! note "Vite 프록시"
    `vite.config.js`에는 `/api`를 다른 서버로 넘기는 개발용 프록시도 있습니다. `.env`에 주소를 적으면 요청이 프록시를 거치지 않으므로 신경 쓰지 않아도 됩니다. 실험 스택의 Admin BE에 붙여 보고 싶을 때만 `VITE_API_BASE_URL`을 비우고 프록시 대상(`server.proxy["/api"].target`)을 그 주소로 바꿔 씁니다. 이 변경은 커밋하지 않습니다.

## 3. 린트와 빌드

```bash
pnpm lint     # ESLint. 오류만 실패로 본다(경고는 통과)
pnpm build    # dist/ 에 배포용 파일 생성
pnpm preview  # 빌드 결과를 로컬에서 열어 보기
```

PR을 올리면 CI가 `pnpm install --frozen-lockfile` → `pnpm run lint` → `pnpm run build`를 돌리고, 통과해야 병합할 수 있습니다. 이 저장소에는 **자동 테스트가 없습니다.** 화면 동작은 직접 띄워서, 또는 실험 스택에 배포해서 확인합니다.

접속 정보(SSH 명령, Jupyter 주소)를 만드는 함수만 따로 점검하는 스크립트가 있습니다. `src/utils/decsMapper.js`를 고쳤다면 돌립니다.

```bash
node src/utils/decsMapper.check.mjs
```

## 4. 개발 서버 실행

```bash
pnpm dev
```

`http://localhost:30081`에 접속합니다(포트는 `vite.config.js`의 `server.port`). 파일을 저장하면 화면이 바로 바뀝니다.

로그인하면 권한에 따라 `/user` 또는 `/admin`으로 이동합니다. 로컬 DB에 관리자 계정이 없다면 가입한 뒤 DB에서 그 사용자의 `role`을 `ADMIN`으로 바꿉니다.

## 5. 막혔을 때

| 증상 | 확인할 것 |
| --- | --- |
| `pnpm install`이 잠금 파일 오류로 끝남 | `package.json`만 고치고 `pnpm install`을 다시 돌리지 않았는지. 돌려서 생긴 `pnpm-lock.yaml` 변경을 같이 커밋한다 |
| 화면은 뜨는데 모든 요청이 실패 | 브라우저 개발자 도구 Network 탭에서 요청 주소가 `.env`의 값인지, Admin BE가 떠 있는지 |
| 요청이 CORS 오류로 막힘 | Admin BE의 `deployment.frontend.local`이 개발 서버 주소(포트 포함)와 같은지 |
| `.env`를 고쳤는데 반영 안 됨 | 개발 서버를 껐다 켠다. 환경 변수는 시작할 때만 읽는다 |
| 로그인 직후 닫을 수 없는 창이 뜸 | 정상. 우분투 유저네임이 없는 계정은 등록해야 다음으로 넘어간다 |
| 승인한 신청이 계속 "처리 중" | 로컬에는 config-server가 없어 생성 작업이 끝나지 않는다. 그 뒤 흐름은 실험 스택에서 확인한다 |
| 린트 경고가 많이 뜸 | 경고는 CI를 막지 않는다. 다만 새로 쓰는 코드에서는 경고를 남기지 않는다([디자인 시스템과 다국어](디자인-시스템-다국어.md) 3절) |

여기까지 됐다면 [화면과 코드 구조](화면-코드-구조.md)로 넘어갑니다.
