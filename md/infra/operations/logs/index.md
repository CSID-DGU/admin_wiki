# 운영 로그

config-server와 operation 스택을 운영하면서 생긴 일을 날짜별로 모아 두는 목록이다. 장애, 복구, 배포, 실험처럼 "그때 무슨 일이 있었고 무엇을 했는지"를 한 건에 한 문서로 남긴다.

평소에 따르는 절차는 [운영 매뉴얼](../운영-매뉴얼.md)에 둔다. 로그에서 얻은 결론 때문에 절차가 바뀌면 운영 매뉴얼을 고치고, 로그에는 고친 절을 링크한다.

NAS, 노드의 Kerberos 클라이언트, NFS 마운트 자체의 문제는 [Kerberos/NFS 디버깅 로그](../../../system/kerberos-nfs/debugging/index.md)에 둔다. config-server가 만든 계정·홈 디렉터리·Pod·NodePort에서 생긴 일이면 여기에 둔다.

## 기록 목록

최근 기록을 위에 둔다.

| 날짜 | 상태 | 제목 | 한 줄 결론 |
| --- | --- | --- | --- |
| 2026-11-03 | 진행 중 | [Pod별 독립 NFS client 도입](Pod별-NFS-client.md) | 작성 예정 |

상태는 다음 뜻으로 쓴다.

- **진행 중**: 아직 조사하거나 조치하고 있다.
- **조치 완료**: 증상은 없어졌지만 원인은 확정하지 못했다.
- **원인 확정**: 원인을 증거로 확인했고 조치까지 마쳤다.
- **작업 기록**: 장애가 아니라 배포·이전·정리 같은 계획된 작업을 남긴 것이다.

## 새 로그 추가하기

1. 이 폴더(`md/infra/operations/logs/`)에 파일을 만든다. 이름은 `주제.md`로 하고 날짜는 넣지 않는다. 날짜는 기록 목록 표와 본문 맨 위 표에 적는다. 예: `Pod-재시작-실패.md`
2. 아래 [본문 형식](#로그-본문-형식)대로 쓴다.
3. 위 기록 목록 표 맨 위에 한 줄을 넣는다.
4. `mkdocs.yml`의 nav에서 `infra → 운영 → 로그` 아래에 한 줄을 넣는다. 빠뜨리면 페이지는 만들어지지만 왼쪽 메뉴에 보이지 않는다.

```yaml
      - 운영:
          # ...
          - 로그:
              - 목록: infra/operations/logs/index.md
              - Pod 재시작 실패: infra/operations/logs/Pod-재시작-실패.md
```

위키 빌드는 `--strict`로 돌기 때문에 링크가 하나라도 깨지면 배포가 멈춘다. push 전에 링크 경로를 한 번 확인한다.

## 로그 본문 형식

결론을 맨 앞에 쓴다. 처음 읽는 사람이 요약만 보고도 무슨 일이었는지, 지금 무엇을 조심해야 하는지 알 수 있어야 한다.

````markdown
# 무엇이 어떻게 됐는지 한 문장

| 항목 | 내용 |
| --- | --- |
| 날짜 | 2026-11-07 ~ 2026-11-08 |
| 상태 | 원인 확정 |
| 범위 | 스택, 노드, 사용자·Pod, config-server 버전 |
| 관련 문서 | 운영 매뉴얼 절, 이슈·PR 링크 |

## 요약

무슨 일이 있었고, 원인은 무엇이었고, 무엇을 했는지 세 문장 안으로 쓴다.

## 경과

시각 순서로 쓴다. 관측한 것과 직접 한 일을 구분한다.

## 원인

확인한 사실과 아직 추정인 것을 나눠 쓴다.

## 조치

임시 조치와 영구 조치를 나누고, 되돌리는 방법도 적는다.

## 남은 일

후속 작업과 운영 매뉴얼에 반영할 내용을 적는다.

## 근거

명령 출력, 로그 위치, 커밋, 스크립트를 적는다.
````

keytab, SSH 개인키, DB 비밀번호, 토큰의 실제 값은 로그에도 적지 않는다. 명령 출력을 붙일 때 이런 값이 섞여 있지 않은지 확인한다.
